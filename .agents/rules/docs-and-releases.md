# Docs and releases

- **DR1:** The documentation pages are `docs/*.md`. `website/` builds them with Docusaurus (exact versions in `website/package.json` and the pnpm lockfile, a digest-pinned Node image, no network during the build), and `.github/workflows/docs.yml` deploys `website/build` to https://psyb0t.github.io/servicepack/. The theme in `website/src/css/theme.css` is shared with the other psyb0t project sites. The site title equals the README H1. Pages are plain CommonMark; `website/prepare.py` refuses Liquid.
- **DR2:** Every page has front matter with `title`, a 50 to 170 character `description` and `sidebar_position` (the home page also has `slug: /`). Link other pages by their relative `.md` path. Links from `docs/` to files outside it use full `https://github.com/psyb0t/servicepack/blob/main/<path>` URLs (`tree/` for directories). README links to the site use full `https://psyb0t.github.io/servicepack/...` URLs.
- **DR3:** After a docs change, run `make docs` (it fails on a broken link or anchor), then `make docs-preview` and check desktop and phone widths and search. After changing a package version, run `make docs-lock` and `make docs-audit`.
- **DR4:** `CHANGELOG.md` entries are `## vX.Y.Z (YYYY-MM-DD)`, a one-line summary, then bullets in the past tense ("Fixed", "Updated", "Added") that say what a downstream must do, if anything.
- **DR5:** Commit subjects for releases start with the version: `vX.Y.Z: <what changed>`.
- **DR6:** A release is an annotated `vX.Y.Z` tag on a commit whose `main` pipeline run passed. The tag message's first line is exactly `vX.Y.Z`, then a blank line, then that version's CHANGELOG section.
