# servicepack

Instructions for coding agents (Codex, Claude Code and others) and for people changing this repository. People who want to build on servicepack want the documentation site, https://psyb0t.github.io/servicepack/, not this file.

## Agent setup

`CLAUDE.md` is a committed symlink to `AGENTS.md`, and `.claude` is a committed symlink to `.agents`, so Claude Code reads the same instructions, rules and skills as Codex. Claude's Edit and Write tools refuse to write through a symlink, so edit `AGENTS.md` and `.agents/` files directly.

`make servicepack-update` never copies `AGENTS.md`, `CLAUDE.md`, `.claude` or `.agents` into a downstream project: they are in the update's mechanical floor in `scripts/make/servicepack/do_update.sh`. These files describe this repository only.

## What it is

A clone-and-own Go application template, not a library to add to an unrelated project. It runs in-process services concurrently for local debugging, and a downstream deploys the result as one binary or splits services into separate deployables. `make own` turns a fresh clone into a new project, and `make servicepack-update` later brings framework changes into it.

## Architecture

- `cmd/main.go`: the entry point. It sets the process-wide `binary`, `commit` and `version` scope fields and starts the app.
- `internal/app/`: the application lifecycle wrapper.
- `internal/pkg/service-manager/`: concurrent service orchestration (ordering, readiness, retries, allowed failures, shutdown). Its README has the exact semantics.
- `pkg/runner/`: signal-aware lifecycle runner with the whole-application shutdown deadline. Its README has the details.
- `internal/pkg/services/`: the services, plus the generated `services.gen.go` registration.
- `scripts/make/servicepack/`: the updateable framework Make scripts; `scripts/make/` holds project overrides.

## Layout

| Path | What it holds |
| --- | --- |
| `cmd/` | `main.go` (framework) plus the `init.go` and `commands.go` extension points |
| `internal/app/`, `internal/pkg/service-manager/`, `pkg/runner/` | Framework code |
| `internal/pkg/services/` | Services and generated registration |
| `scripts/make/servicepack/` | Framework Make scripts, including the update and `own` flows |
| `docs/` | The documentation site (GitHub Pages, Jekyll, Just the Docs); a downstream's own docs after `make own` |
| `tests/` | The testcontainers harness and service tests |
| `.agents/skills/servicepack/` | The public usage skill, published to ClawHub |

## Commands

Build, lint, generation, dependency and test commands are Docker-backed Make targets. Do not substitute raw host `go` commands.

```bash
make service NAME=myservice      # scaffold and register a service
make service-registration        # regenerate services.gen.go
make build                       # static binary in build/
make test                        # race-enabled suite, Docker available to tests
make test-integration            # uncached race suite, 10-minute timeout
make test-coverage               # 90% framework coverage floor
make lint                        # shfmt, ShellCheck, go fix check, golangci-lint
make lint-fix                    # apply supported fixes; review the diff
make format                      # gofumpt and shfmt
make sec                         # security checks, writes sec.sarif
make docs                        # build the documentation site into .testing/docs-site
make help                        # every target
```

## Project-specific landmines

- Every file outside the update floor and the downstream's `.servicepackupdateignore` is overwritten in every downstream project on its next update. A change to framework code ships to all of them.
- A new per-project file at the repo root (prose, agent instructions, local config) needs a floor entry in `do_update.sh`, or the update copies servicepack's version over the downstream's.
- `services.gen.go` is generated by `make service-registration`. Never edit it.
- `vendor/` is committed. Use `make dep` and the `make pkg-*` targets; never edit module metadata or vendored source by hand.

## Rules

Rules for every change live in `.agents/rules/`, one file per topic. Read the ones that match what you are touching before editing.
